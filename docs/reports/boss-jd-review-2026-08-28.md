# BOSS JD 语义门审计（2026-08-28）

## 结论

旧链路并非只看标题：Userscript 会打开详情并把完整 JD 交给 LLM。但标题/摘要排除词仍会在完整 JD 前硬拦，LLM 规则也把“工程师、全栈、产品经理、垂直行业”判得过窄，形成系统性漏投。

已将关键词降为召回提示，薪资、重复、公司黑名单、非技术角色和风控仍是硬门；最终方向判断改为读取完整 JD 后按实际职责判断。

## 历史样本

ledger 中有 483 条 `llm_reject`、32 条 `llm_error`；其中 251 条被拒岗位的标题含 AI、Agent、智能体、大模型、LLM、应用、FDE、效能或研发。这 251 条不是全部误拒，但证明旧规则需要抽样复核。

明确误拒且新规则已用真实本地模型复核放行：

| 岗位 | 旧拒绝原因 | 完整 JD 证据 | 新结果 |
| --- | --- | --- | --- |
| AI智能体开发工程师 / 好卓数据 | 医疗算法与工程交付不算目标 | Agent 架构、ReAct、memory/tool use、多智能体、RAG、工程部署 | allow 0.90 |
| Agent产品经理 / 上海语生科学技术 | 产品规划/PRD，缺架构交付 | B 端 Agent、行业工作流、私有化、跨团队交付、0→1 | allow 0.88 |
| AI技术工程师 / 阿网科技 | 偏算法，缺业务诊断 | B 端大模型落地、RAG、Agent、行业方案、POC→产品 | allow 0.90 |
| 上海软件开发工程师（AI方向）/ 鑫互联 | 普通后端 | B 端多智能体平台、核心模块、LLM 编排/RAG、工程交付 | allow 0.85 |
| AI应用开发工程师 / 上海咯曜咨询管理 | 普通 AI/全栈 | LangChain/大模型 API、端到端 AI 应用研发与产品优化 | allow 0.90 |

仍应拒绝：纯量化、纯 CV/机器人/芯片硬件、自动驾驶本体研发、AI Infra，以及 AI 只作为宣传背景或普通工具且没有研发、交付、提效、产品化责任的岗位。
