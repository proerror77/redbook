# Agentwashing

> 来源：docs/reports/grok-research-2026-07-17.md | 最后更新：2026-07-17

## 核心痛点

- 把聊天助手、自动补全或单步自动化都称为 agent，会掩盖任务边界、自治程度和真实交付能力。
- agent 名称越宽泛，企业越难比较产品、定义 ROI 和配置匹配的治理措施。
- 市场预测中的“agent 采用率”可能混合了不同能力层级，不能直接等同于生产规模化。

## 高价值角度

- 先判断它是 assistant、automation 还是 task agent，再讨论是否值得导入。
- 用可交付结果、工具调用、跨步骤执行、人工审批和审计链定义 agent，而不是用产品名称定义。
- 把“采用率很高”与“企业级 EBIT、流程重设计和高风险场景信任”分开验证。

## 今日信号（2026-07-17）

- Gartner 在任务型 agent 预测中明确警告 agentwashing：到 2026 年底约 40% 的企业应用可能集成任务特定 agent，但“应用集成”不等于所有功能都具备同等自治能力。[来源](https://www.gartner.com/en/newsroom/press-releases/2025-08-26-gartner-predicts-40-percent-of-enterprise-apps-will-feature-task-specific-ai-agents-by-2026-up-from-less-than-5-percent-in-2025)
- McKinsey 的公开摘要显示 agent 实验广泛，但在任一业务功能内报告已扩展 agentic 系统的比例不超过 10%；评估应回到 workflow redesign、成本和可衡量结果。[来源](https://www.mckinsey.com/capabilities/quantumblack/our-insights/the-state-of-ai)
